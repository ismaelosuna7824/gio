# Automatic tiling for Gio

## Objective
Make Gio arrange eligible windows in each display's active virtual workspace rather than merely parking inactive workspaces. First diagnose and repair the live AX movement failure observed with Accessibility granted: `operationFailed(AXWindowError.unsupportedWindow, rollbackFailures: [])`. The user confirmed Quit Gio restored visible windows. Use public APIs with SIP enabled; do not equate mock tests with real AX, low-latency or visual smoothness.

## Scope and acceptance
- Start with an explicit, deterministic balanced binary split of eligible active windows, with configurable outer/inner gap and a safe usable display rect. No private compositor, permanent capture, or per-frame AX writes.
- Eligibility must not silently tile unknown or non-resizable windows; keep them unmanaged and show actionable state. A visible opt-in for automatic tiling avoids suddenly rearranging all existing desktop windows; new eligible windows are then managed on the enabled display.
- Bridge must distinguish AX attribute failures from request-versus-observed geometry mismatches, including macOS clamping, and preserve recovery/quit safety. A rejected window must not corrupt workspace membership or strand other windows.
- Position and size application must be transactional with physical rollback, and only commit model state after success. Reflow should be triggered by explicit actions and coalesced lifecycle events, not polling.
- Menu provides enable/disable tiling and gap adjustment; user can restore original window frames by disabling safely or Quit. A manual one-monitor AX scenario and two-monitor/performance validation remain required and can be blocked by hardware/user permission.
- Out of scope initially: compositor animation, full Hyprland layout set, app-wide rules engine, installer and unsupported fullscreen windows.
